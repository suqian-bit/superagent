# 可视化面板 PRD

> **一句话**：把现在散落在 `digest stats / sqlite3 / journalctl / cat *.log` 的状态信息聚合成**一个网页**，绑域名 `knowledge.agentforge.com.cn` + Basic Auth，浏览器随时打开看全貌。

---

## 1. 背景

当前要看库存状态、cron 运行情况、推送失败原因，得 ssh 进去敲一堆命令：

```bash
ssh -i ~/.ssh/id_ed25519_codex_server root@154.9.232.37
digest stats
digest list --limit 20
sqlite3 /www/knowledge/index.db "SELECT ..."
tail /var/log/review_pusher.log
tail /var/log/weekly_report.log
systemctl --user status hermes-gateway-knowledge
journalctl --user -u hermes-gateway-knowledge -n 50
```

**痛点**：没全貌、慢、得记命令、手机看不了。

---

## 2. 目标

| 维度 | 目标 |
|------|------|
| 访问方式 | 浏览器打开 `https://knowledge.agentforge.com.cn`，输入用户名密码就看全貌 |
| 端到端延迟 | 页面加载 < 3 秒（数据全部本地 SQLite + log 文件）|
| 实时性 | 默认数据是当时查询的，不需要自动刷新；提供"刷新"按钮 |
| 信息覆盖度 | ≥ 95% 当前 ssh 命令能拿到的信息 |
| 维护成本 | 加一个图表 < 5 分钟（Streamlit 单页就足够）|

---

## 3. 用户故事

**作为主人**，我希望：

1. **早上想看"昨天收了什么"** → 打开页面，KPI 区看到"昨日新增 N 条"，往下表里看具体标题。
2. **下午想看"复习推送有没有按时跑"** → 看"定时任务运行日志"区，最近 3 天每次推送时间 + 是否送达 + 主人回复了没。
3. **想知道库的整体方向偏向** → 看"主题热度"和"标签云"。
4. **某天觉得"系统是不是挂了"** → 看"系统状态"区，systemd / cron / 磁盘 一眼判断。
5. **想看某条详细内容** → 在最近收集表点击 id，展开 md 全文。

### 4.2 各区块详细规格

#### 区块 1: KPI 卡片

| 指标 | 数据源 | SQL/逻辑 |
|------|--------|---------|
| 总收录 | items 表 | `COUNT(*) WHERE archived=0` |
| 本周新增 | items 表 | `COUNT(*) WHERE created_at >= now-7d AND archived=0` |
| 平均分 | items 表 | `AVG(score_total) WHERE archived=0` |
| 待复习 | items 表 | `COUNT WHERE review_enabled=1 AND archived=0 AND next_review_at <= now` |
| 未答推送 | push_history | `COUNT WHERE response_quality IS NULL AND mode != 'weekly' AND pushed_at >= now-24h` |

#### 区块 2: 收集趋势

- X 轴：最近 14 天日期
- Y 轴：当日新增条数
- 按 tier 堆叠（A 绿 / B 蓝 / C 灰）
- `GROUP BY date(created_at), tier`

#### 区块 3: tier 饼图

`GROUP BY tier FROM items WHERE archived=0`

#### 区块 4: 平台饼图

`GROUP BY platform FROM items WHERE archived=0`

#### 区块 5: Top 高价值内容表

```sql
SELECT id, title, tier, weight, score_total, created_at, file_path
FROM items WHERE archived=0
ORDER BY weight DESC, score_total DESC
LIMIT 20
```

点击行展开 → 读 `file_path` 显示 md 全文（用 `st.markdown`）。

#### 区块 6: 主题热度

**柱状图**：`SELECT name, count FROM categories ORDER BY count DESC`
**标签云**：`SELECT name, count FROM tags ORDER BY count DESC LIMIT 30`（用 wordcloud 库或者纯文字 + font-size 映射）

#### 区块 7: 项目档案

```sql
SELECT p.name, p.display_name, p.status, p.updated_at, p.file_path,
       COUNT(ip.item_id) AS linked_count,
       AVG(ip.relevance) AS avg_relevance
FROM projects p
LEFT JOIN item_projects ip ON p.id = ip.project_id
WHERE p.archived=0
GROUP BY p.id
```

点击展开 → 读 md + 列出关联的 items（按 relevance DESC）。

#### 区块 8: 定时任务

| 子区 | 数据源 |
|------|--------|
| 复习推送 | `SELECT * FROM push_history WHERE mode IN ('soul','associate','apply','drop') ORDER BY id DESC LIMIT 10` |
| 周报 | `SELECT * FROM push_history WHERE mode='weekly' ORDER BY id DESC LIMIT 4` |
| 心跳推送 | `SELECT * FROM push_history WHERE mode='heartbeat' ORDER BY id DESC LIMIT 7` |
| 失败日志 | `grep -E "ERROR\|Failed\|Exception" /var/log/review_pusher.log /var/log/weekly_report.log` |
| systemd | shell out `systemctl --user is-active hermes-gateway-knowledge` |
| crontab | shell out `crontab -l` |
| 磁盘 | shell out `df -h /www` |
| 数据库大小 | `du -sh /www/knowledge/index.db` |

### 6.1 选型理由

| 选型 | 为什么 |
|------|--------|
| Streamlit | 1-2 小时出 v0.1，加图表 1 行代码，跟现有 Python 栈一致 |
| Nginx 反代 | 已有的 nginx，加 server block 顺手 |
| Basic Auth（nginx 层）| 比应用层 token 验证简单且安全，浏览器原生支持 |
| Let's Encrypt（certbot）| 跟 dify/openclaw/obsidian 三个子域同款 |
| systemd --user | 跟 hermes-gateway-knowledge 同款托管 |

## 7. 部署步骤

### 7.1 用户侧（在域名 DNS 处加 A 记录）

```
type: A
name: knowledge
value: 154.9.232.37
ttl: 600
```

### 7.2 服务器侧（自动化）

```bash
# 1. 装 streamlit + plotly + wordcloud
/www/content_fetcher_venv/bin/pip install streamlit plotly wordcloud pillow

# 2. 写 dashboard.py 到 _lib/
# 3. 配 systemd unit dashboard.service
# 4. 启动 systemctl --user start dashboard

# 5. 配 nginx site
sudo tee /etc/nginx/sites-available/knowledge << 'EOF'
server {
    listen 80;
    server_name knowledge.agentforge.com.cn;
    location /.well-known/acme-challenge/ { root /var/www/certbot; }
    location / { return 301 https://$host$request_uri; }
}
server {
    listen 443 ssl;
    server_name knowledge.agentforge.com.cn;

    ssl_certificate /etc/letsencrypt/live/knowledge.agentforge.com.cn/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/knowledge.agentforge.com.cn/privkey.pem;

    auth_basic "knowledge dashboard";
    auth_basic_user_file /etc/nginx/.htpasswd_knowledge;

    location / {
        proxy_pass http://127.0.0.1:8501;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        # WebSocket（Streamlit 需要）
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 86400;
    }
}
EOF

# 6. 软链 + 测试 + 重载
sudo ln -sf /etc/nginx/sites-available/knowledge /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx

# 7. 申请证书（DNS 记录生效后）
sudo certbot certonly --webroot -w /var/www/certbot \
  -d knowledge.agentforge.com.cn \
  --email <your-email>

# 8. 生成 basic auth 密码
htpasswd -c /etc/nginx/.htpasswd_knowledge wjh
# (会提示输密码两次)

# 9. 验证
curl -u wjh:<password> https://knowledge.agentforge.com.cn/
```

## 8. 安全

1. **Basic Auth** 兜底——所有路径都要密码
2. **HTTPS 全程**（HTTP 自动跳转 443）
3. **Streamlit 只监听 127.0.0.1**，不直接暴露
4. **UFW 不开 8501**（保持 deny）
5. 密码强度 ≥ 14 位，存到 1Password / 浏览器密码管理器
6. fail2ban 已经在跑，自动封暴力试密码

- 修改全部用 `subprocess.run(["digest", "promote", ...])` 调 CLI（不用 shell=True，防注入）

- 数据完整性保证：所有写操作走现有 `digest` / `project` 命令，不绕过业务逻辑
