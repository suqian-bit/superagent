# 从"被动仓库"到"主动连接"

> 当天主人提了一个核心问题：知识库的积累方式有了，但**怎么激发使用**？
> 这个判断改变了项目的下一阶段方向。

---

## 触发问题

主人原话：

> "在 app 积累，和在这里积累，只要没用起来就区别不大。怎么能激发着用起来，去做探索，
> 或者怎么能和我当前的事情结合起来？比如我当前正在搞量化投资，正在学习大模型，
> 我原本已经有了一些代码和基础，怎么能和知识库接起来，来判断能不能用在我当前上，
> 以及如果当前用不上，怎么能激发出来去使用。"

这个问题的本质：之前所有功能都是"被动收纳" → 真正的助理应该**在你工作时主动出现**。

---

## 本质判断

### 当前形态

```
你发链接 → 我存 → 等你问 → 我答
        ↑
   "知识仓库"
```

价值 ≈ 防丢失 + 复习提醒 ≈ 比飞书收藏夹好 30%

### 真正想要的形态

```
你正在做事 → 我看到了相关的库存 → 主动告诉你"这里有"
                                       ↑
                                  "知识助理"
```

价值 ≈ 防丢失 + 复习 + **降低"想不起用"的损失** ≈ 比收藏夹好 5 倍

### 关键缺口

助手对主人的认知**只有**：
- 名字、open_id
- 收过 N 条内容

**完全不知道**：
- 主人正在搞量化投资（有代码、有策略、有具体卡点）
- 主人正在学大模型（hermes 实战，做到什么程度）
- 主人的技能栈、长期目标
- 项目目录、代码长什么样

所以**即使库里有"训练/回测时间分离"这种关键知识，它也想不起来主人正在写的量化代码里可能踩这个坑**。

---

## 分层方案

### 🅰️ 第 1 层：建立"项目档案"（**地基**）

在服务器上建：

```
/www/knowledge/projects/
├── quant.md              # 量化项目档案
├── llm-agent.md          # 大模型学习档案
└── me.md                 # 用户人物画像
```

每个 md 写：

```markdown
---
project: quant
status: in-progress
started: 2026-04-01
---

# 量化投资项目

## 目标
- 用 AI / 强化学习做美股 + 加密的量化策略
- 实现一个能跑实盘的看板系统

## 当前进度
- ✅ Freqtrade 部署
- ✅ 策略回测框架（backtrader）
- 🚧 实时数据接入（在调 ccxt）
- ⏳ 多时间周期信号融合
- ⏳ 板块轮动模型

## 卡点 / 想学的
- 训练/回测时间切分怎么严格？
- 多 AI Agent 协作做不同任务（情绪/基本面/技术面）
- 实时新闻舆情怎么用？

## 代码位置
/root/quant_strategies/
```

**这份档案是"主人的世界观注入"**。每条新内容入库时，多调一步 LLM 评估"对哪些项目相关、关联度多少"，存到新表 `item_projects`。

工作量：1-2 小时。

---

### 🅱️ 第 2 层：入库时主动提示"这条对你有用"

```
你发：「http://xhslink.com/o/xxx」
助理回：
  📌 精华...
  
  ━━━━━━━━━━━━━━━━━━
  🎯 跟你正在做的事关联
  ━━━━━━━━━━━━━━━━━━
  ⭐ quant 项目（关联度 85）
     卡点匹配：你提到的"训练/回测时间切分"，
     作者明确说了用时间轴切断的方法。
     建议：今天先看，明天用到 backtest.py 上。
  
  💡 llm-agent 项目（关联度 40）
     作者用多 Agent 分工（情绪/基本面/技术面），
     跟你的多 profile 思路一致。
```

**入库时就告诉主人"这条该立刻用还是慢慢学"**，而不是等他想起来。

---

### 🅲️ 第 3 层：场景化检索

```bash
digest impact "我现在要给 momentum 策略加多时间周期"
```

库里搜：
1. 项目档案里相关的卡点
2. 历史内容里跟场景相关的（用 RAG embedding）
3. 拼成"你以前收过这几条可能能用：..."

或者更口语化：飞书说"我现在卡在 XXX 上"，助理自动联系上下文给建议。

---

### 🅳️ 第 4 层：项目档案反查老库存（**最关键**）

每次项目档案更新（主人写"加了一个新卡点"）→ 助理自动**反向扫库**找以前收过但忘了用的内容：

```
你刚才更新了 quant.md，加了卡点："实时新闻舆情分类"。

我帮你翻了一下库，**id=5 这条 4 天前收的"AI 炒股"视频里**讲了
舆情系统通过高频关键词+理解模型做相关性分析。
你当时没标"立刻用"，要不要现在看一下？
```

这一步**直接打到痛点**——以前你没意识到能用，等真要用了才发现忘了。

---

### 🅴️ 第 5 层：直接对接代码

最深的形态。给助理读权限 grep 主人的：
- `/root/quant_strategies/`
- `/root/.hermes/profiles/knowledge/skills/`

收到新内容时能精确说：

> "这跟你 `quant_strategies/momentum.py:42` 那段时间窗逻辑有关，建议改成 ..."

这是**AI 研发助理**——和项目深度共生。

---

## 建议落地节奏

| 阶段 | 内容 | 工时 | 触发条件 |
|------|------|------|---------|
| Phase 1 | 🅰️ 项目档案 + 🅱️ 入库时关联评估 | 2-3 小时 | 主人写好 quant.md / llm-agent.md / me.md |
| Phase 2 | 🅲 场景化检索 + 周报加项目段 | 2 小时 | Phase 1 跑 1 周 |
| Phase 3 | 🅳 档案反查 | 2 小时 | 库存 30+ 条 |
| Phase 4 | 🅴 代码对接 | 1 天+ | 等真有动力做时 |

---

## 副发现：复习推送的静默问题

实施这个思考的当天，主人问"为啥没推送飞书定时消息？"

诊断结果：cron 正常，但**今天没有任何 due item**——所有 A 级 item 的 `next_review_at` 都在 1-3 天后。系统按设计静默。

但主人**期待"每天 9/13/21 各推一条"**，体验上就觉得"系统没工作"。

**这正好是"激发使用"的另一面**：

- 库存少 + 严格 SM-2 间隔 = 几乎全天静默
- 静默 = 主人忘了助理存在 = 主动收录的动机也下降 = 死循环

### 改进方向（候选）

**方案 A：兜底"积压/关心"消息**

如果今天 0 个 due item，仍然推一条：
- 关心型：「今天 5 条都还没到复习时间，要不要看 id=X 那条新的 OpenSpec？」
- 项目型：「你昨天收的 X 跟你 quant 项目相关度 85%，要不要今天用一下？」
- 反思型：「最近一周没收新内容了，有刷到什么有意思的吗？」

**方案 B：B 级也启动复习**

现在只 A (≥90) 进队列，B (80-89) 也启动但间隔更长（7/14/30）。

**方案 C：管理期待 + 不动**

接受"早期静默"，等库存 30+ 后自然密集起来。

---

## 结论

主人的判断是对的：**"在 app 积累 vs 在这里积累，只要没用起来就没区别"**。

这是项目从**功能完备**走向**真正有用**的分水岭——前面 1 周搞定的"5 步 pipeline + 复习 + 周报"是仓库的骨架，但骨架之上要长出**"和主人当前事情挂钩"的肉**，才有黏性。

下一步：

1. 主人写 `quant.md` / `llm-agent.md` / `me.md`（最难的一步，但只能主人自己写）
2. 我接 pipeline 让每条入库都带"项目关联度"
3. 跑 1 周看效果

如果走通，知识库从"信息归档"变成"研发陪伴"，性质完全不同。
