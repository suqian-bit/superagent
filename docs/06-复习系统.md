# 复习系统

实现"主动催你消化"的核心模块。基于 [[#SM-2 简化算法]]（间隔重复）+ cron 定时推送 + 用户回复反馈回写。

```
A 级 item 入库 → next_review_at = 1 天后
   ↓
cron 0 1,5,13 * * * (UTC) ≡ 北京 9/13/21
   ↓
review-push 扫描 due → 飞书直推问题
   ↓
你回 "4" 或 "记得"
   ↓
Agent 调 digest pending-review → digest review <id> <q>
   ↓
SM-2 更新：ease ±, idx ±, mastery ±, next_review_at = +N 天
```

---

## SM-2 简化算法

基础间隔：

```python
REVIEW_INTERVALS = [1, 3, 7, 14, 30]  # 天
```

每条 item 有 `review_idx`（0-4，指向 REVIEW_INTERVALS 的位置）和 `ease`（1.3-3.0，难度系数，初始 2.5）。

### 答题质量 → 状态更新

```python
q = 用户答的 1-5

if q >= 4:                            # 答得很好
    ease = min(3.0, ease + 0.15)
    idx = min(idx + 1, 4)              # 间隔拉长
    mastery = min(100, mastery + 15)
elif q == 3:                           # 勉强记得
    ease = min(3.0, ease + 0.05)
    # idx 不变
    mastery = min(100, mastery + 5)
else:                                  # q=1,2 忘了
    ease = max(1.3, ease - 0.2)
    idx = max(0, idx - 1)              # 间隔回退
    mastery = max(0, mastery - 10)

# 计算下次时间
base_days = REVIEW_INTERVALS[idx]
actual_days = base_days * (ease / 2.5)    # ease 影响实际间隔
next_review_at = now + actual_days
```

### 行为模拟

假如 id=3 初始 idx=0, ease=2.5, mastery=0：

| 第 N 次答 | quality | idx | ease | mastery | 下次间隔（天）|
|----------|---------|-----|------|---------|------------|
| 1 | 4 | 1 | 2.65 | 15 | 3 × 2.65/2.5 ≈ 3.2 |
| 2 | 5 | 2 | 2.80 | 30 | 7 × 2.80/2.5 ≈ 7.8 |
| 3 | 3 | 2 | 2.85 | 35 | 7 × 2.85/2.5 ≈ 8.0 |
| 4 | 1 | 1 | 2.65 | 25 | 3 × 2.65/2.5 ≈ 3.2（回退）|

效果：**答对了越来越久才推，答错了立刻拉回**。

## 启动条件

只有 tier A（[[03-评分与分级#Tier 阈值|score_total ≥ 90]]）自动启用：

```python
# save.py
review_enabled = 1 if score_total >= 90 else 0
if review_enabled:
    next_review_at = pipeline_io.add_days(1)  # 第一次 1 天后
```

tier B/C 不进复习队列，归入知识库。

### 主人手动调级（**2026-05-13 新增**）

如果主人觉得某条 B/C 级也值得复习，可以用 `digest promote`：

```bash
digest promote <id>           # 推到 A，自动启动复习（明天开始）
digest promote <id> --tier B  # 推到 B（仍然不启动复习）
digest demote <id>            # 推到 C，停止推送
digest demote <id> --archive  # 彻底归档（查询/推送都看不到）
digest view <id>              # 看一条详细
```

在飞书可以直接说"这条提到 A"、"降到 C"、"归档"，Agent 会调对应命令（SOUL.md 已写规则）。详见 [[08-命令速查#digest 命令]]。

## 推送流程：`review-push`（cron 定时跑）

脚本：`/root/.hermes/profiles/knowledge/skills/_lib/review_pusher.py`  
软链：`/usr/local/bin/review-push`

```python
def main():
    1. 连接 /www/knowledge/index.db
    2. pick_due_item(conn):
       SELECT * FROM items WHERE
         review_enabled=1 AND archived=0
         AND next_review_at <= now
         AND NOT EXISTS (今天已推过的)         ← 同日去重
       ORDER BY
         CASE tier WHEN 'A' THEN 0 WHEN 'B' THEN 1 ELSE 2 END,
         next_review_at ASC
       LIMIT 1
    3. pick_question(item_id):
       从 questions 表随机选一条
    4. build_push_text(item, question):
       根据条件选模式（soul/associate/apply/drop）
       格式化文案
    5. send_to_feishu(text):
       拿 tenant_access_token
       POST /open-apis/im/v1/messages?receive_id_type=open_id
    6. push_history INSERT 记录这次推送
```

### 4 种推送模式

| 模式 | 何时用 | 文案样例 |
|------|-------|---------|
| **soul** 灵魂提问 | 默认 | 🧠 复习一下：\n\n{question}\n\n（来自《{title}》，{N} 天前；答完回我 1-5 分）|
| **associate** 联想题 | 默认 | 🔗 顺手考你一下：\n\n《{title}》里讲过的——{question}\n\n（30 秒回我 1-5 分）|
| **apply** 实战题 | 默认 | ⚙️ 实战题：\n\n{question}\n\n（出自《{title}》；放空 1 分钟再回 1-5）|
| **drop** 淘汰询问 | review_count>=3 且 mastery>50 时 | ❓{N} 天前你收了《{title}》，回「留」或「删」 |

soul/associate/apply 三种默认随机选，避免每天都同一种问法。

### 同一天去重

```sql
NOT EXISTS (
  SELECT 1 FROM push_history p
  WHERE p.item_id=i.id
    AND substr(p.pushed_at, 1, 10) = '2026-05-12'  -- 北京时区今天
)
```

cron 一天跑 3 次（9/13/21），如果上午已经推过 id=3，下午就不再推这条，会找别的 due item。

## 反馈回写：`digest pending-review` + `digest review`

由 Agent 在 [[07-Hermes-Skill链路]] 的 SOUL.md 引导下完成。

### Step 1: `digest pending-review`

查最近 24 小时内推过但还没答的：

```sql
SELECT p.id, p.item_id, p.question, p.pushed_at,
       i.title, i.tier
FROM push_history p
JOIN items i ON p.item_id = i.id
WHERE p.response_quality IS NULL
  AND p.pushed_at >= (北京时间 24h 前)
ORDER BY p.pushed_at DESC
```

返回的第一条就是主人在答的那条。

### Step 2: Agent 判断 quality 1-5

如果主人回了数字 → 直接用。

如果是文字 → 按映射表：

| 主人原话特征 | quality |
|------------|---------|
| "完全忘了/不记得了/啥都没记住" | 1 |
| "模糊记得/印象不深/大概是" | 2 |
| "差不多对/凑合/对了一部分" | 3 |
| "答对了/记得/清楚" | 4 |
| "完全对+能举一反三/还能扩展" | 5 |

### Step 3: `digest review <item_id> <quality>`

更新两张表：

```sql
-- items: SM-2 更新
UPDATE items SET
  review_idx = ?,
  ease = ?,
  review_count = review_count + 1,
  last_reviewed_at = NOW(),
  next_review_at = ?,
  mastery = ?
WHERE id = ?;

-- push_history: 标记这条 pending 已答
UPDATE push_history SET
  response_at = NOW(),
  response_quality = ?
WHERE id IN (
  SELECT id FROM push_history
  WHERE item_id = ? AND response_quality IS NULL
  ORDER BY pushed_at DESC LIMIT 1
);
```

### Step 4: Agent 回主人

脚本返回 `summary_for_agent` 字段：

```
✅ 已记录复习反馈：记得很好（4/5）。
   累计复习 1 次，掌握度 15/100，下次推送：2026-05-16T01:30（约 3 天后）
```

Agent 原样转发给主人。

## 心跳推送（**2026-05-14 新增**）

**问题**：cron 跑了但没 due item 时，主人完全收不到任何消息 → "系统是不是挂了"。

**修复**：没 due 时，**每天早上 9 点**（北京）推一条心跳：

```
☀️ 早上好

📭 今天没该复习的
📥 本周新增 5 条
🔜 下一条复习：《精讲OpenSpec...》（1.7 小时后）

💬 回我「找点东西复习」可手动挑一条；说「我在研究 X」可建项目档案。
```

实现位置：`review_pusher.py` 的 `build_heartbeat_text()`。

### 触发逻辑

```python
if 没有 due item:
    if now.hour == 9:  # 只在早上 9 点（北京）触发
        if 今天没推过任何东西:
            发心跳消息
            push_history 记录 mode='heartbeat'
```

cron 跑 9/13/21 三次：
- 早 9 点没 due → 推心跳
- 早 9 点已经推过任何东西（review/heartbeat/weekly） → 不重复推
- 中午 1 点 / 晚上 9 点没 due → 完全静默

详见 `/root/.hermes/profiles/knowledge/skills/_lib/review_pusher.py` 的 `build_heartbeat_text()`。

## 周报推送（**2026-05-13 上线**）

每周日北京时间 22:00 自动汇总过去 7 天的库存动态，飞书直推。

脚本：`/root/.hermes/profiles/knowledge/skills/_lib/weekly_report.py`
软链：`/usr/local/bin/weekly-report`

### 汇总维度

| 维度 | 数据来源 |
|------|---------|
| 本周收录数 + tier 分布 | `items WHERE created_at >= 7d ago` |
| Top 3 高 weight 内容 | 按 weight DESC 排 |
| 关注主题（top 5 大类）| `categories JOIN item_categories` 聚合 |
| 高频标签（top 8）| `tags JOIN item_tags` 聚合 |
| 复习情况（推送数 / 应答率 / 平均质量） | `push_history` 表 |
| 全库掌握度 | `AVG(mastery) FROM items WHERE review_enabled=1` |
| 当前积压 | `COUNT WHERE next_review_at <= now AND review_enabled=1` |
| **AI 观察** | DeepSeek 看汇总数据生成 3-4 句话 |

### 文案样例

```
📊 本周知识周报
(2026-05-06 ~ 2026-05-13)
━━━━━━━━━━━━━━━━━━

📥 本周收录 4 条 · 平均 66.8/100
  A 级 3 / C 级 1

🏆 Top 高价值
  1. [95·A] Hermes记忆详解，四层架构一次讲透 (id=3)
  2. [95·A] AI干货分享-AI炒股 (id=5)
  3. [92·A] 精讲OpenSpec... (id=6)

📂 关注主题
  AI(4) / 生产力(2) / 投资(2)

🏷 高频标签
  #预警  #量化交易  #量化  #规格驱动开发  #股票  #策略

🧠 复习情况
  推送 1 次 · 回答 1 次 (100%)
  平均质量 4.0/5 · 库总掌握度 5.0/100

💡 AI 观察
  这周你聚焦在 AI、生产力和投资三个方向，新增内容虽少但质量很高
  A 级条目占比 75%，说明筛选意识在增强。
  下周建议重点消化"Hermes 记忆详解"，权重最高且涉及四层架构。

━━━━━━━━━━━━━━━━━━
全库 4 条 · 在飞书发 "看看积压" 看待办
```

### 去重机制

```sql
-- 用 push_history.mode='weekly' 标记，避免同周重复发
SELECT id FROM push_history
WHERE mode='weekly' AND pushed_at >= (now - 6 days)
LIMIT 1
```

如果上周已经推过，再跑 `weekly-report` 会 `skipped`。`weekly-report --force` 可强制重发。

### crontab 配置

```cron
# 周日北京时间 22:00 = UTC 周日 14:00
0 14 * * 0 /usr/local/bin/weekly-report >> /var/log/weekly_report.log 2>&1
```

### 命令

```bash
weekly-report                     # 正常跑（已推过本周就 skip）
weekly-report --dry-run           # 预览文案不真推
weekly-report --force             # 强制再推一次
weekly-report --days 14           # 改成回看 14 天
```
