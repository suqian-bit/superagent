# 2026-05-14 · 从"仓库"到"助理"

> 主人提出的关键问题：
> "积累的途径有了，但和我当前在做的事情怎么结合？怎么激发使用？
> 在 app 积累和在这里积累，只要没用起来就区别不大。"
>
> 这一篇是这次产品转向的思考记录。

---

## 问题诊断

### 当前形态

```
你发链接 → 我存 → 等你问 → 我答
        ↑
   "知识仓库"
```

**症状**：
- 库里有 5 条，每条评分 + 精华都到位
- 但主人**不会主动来查**
- 因为主人在干事时，根本想不起来"我以前收过相关的"
- 收藏价值 ≈ 飞书收藏夹 + 30%（多了评分和复习推送）

### 想要的形态

```
你正在做事 → 我看到了相关库存 → 主动告诉你"这里有"
                                   ↑
                              "知识助理"
```

**关键差**：助理**知道你正在干嘛**，能在你工作时跳出来说"这条对你正在做的 X 有用"。

---

## 关键缺口：库不知道"你是谁"

助理目前对主人的认知：
- 王竞辉，open_id `ou_edf99c...`
- 收过 5 条内容

**不知道**：
- 主人在搞**量化投资**（有代码、有策略、有具体卡点）
- 主人在学**大模型 / Hermes**（已经做到这个项目本身）
- 技能栈、长期目标
- 项目代码位置、当前进度

所以即使库里有"训练/回测时间分离"这种关键知识，它**也想不起来主人正在写的量化代码里会踩这个坑**。

→ **要给助理塞一份"主人的世界观"**。

---

## 分层方案

### 🅰️ 第 1 层：项目档案（**先做这个**）

```
/www/knowledge/projects/
├── quant.md              # 量化投资项目档案
├── llm-agent.md          # 大模型/Hermes 项目档案
└── me.md                 # 用户人物画像
```

每个档案包含：目标 / 当前进度 / 卡点 / 想学的 / 代码位置 / 节奏。

**入库时多调一步 LLM**，对照 projects 评估每条内容：

```json
[
  {"project": "quant",     "relevance": 85, "reason": "命中卡点：训练/回测时间分离"},
  {"project": "llm-agent", "relevance": 40, "reason": "提到多 Agent 协作"}
]
```

存到新表 `item_projects (item_id, project_name, relevance, reason)`。

**这是后面所有层的地基**。工作量 1-2 小时。

### 🅱️ 第 2 层：入库时主动提示

```
📌 精华...

🎯 跟你正在做的事关联：
   ⭐ quant 项目（关联度 85）
      卡点匹配：你提到的"训练/回测时间切分"，作者明确说了用时间轴切断的方法。
      建议：今天就看，明天用到你的 backtest.py。
   💡 llm-agent 项目（关联度 40）
```

主人**入库当下就知道这条可以立刻用**，不用"以后再说"。

### 🅲️ 第 3 层：场景化检索

```bash
digest impact "我现在要给 momentum 策略加多时间周期"
```

在飞书随口说一句"我现在卡在 XXX 上"→ 助理自动联系上下文翻库 + 给建议。

### 🅳️ 第 4 层：项目档案反查老库存

主人更新项目档案时（"加了新卡点：实时舆情分类"）→ 助理自动反查库：

> 你刚才加了卡点"实时舆情分类"。我帮你翻了一下库，
> **id=5 那条"AI 炒股"视频里**讲了舆情系统的高频关键词+理解模型。
> 你当时打的是 40 分 C 级，但其实命中你新卡点。要不要现在看？

**这一步直接打到痛点**：以前没意识到能用，等真要用了才发现忘了。

### 🅴️ 第 5 层：直接对接代码

最深的形态。助理读 `/root/quant_strategies/` 和你的代码，能精确说："这跟你 `momentum.py:42` 那段逻辑可以结合"。

季度级工程量。先不动。

## 主人的关键追加：**项目档案不能让我硬写**

> "我每天或者每间隔一段时间可能在干的事情就会变化，要不你写个 skill？
> 如果我有新的变化，看看怎么能触发，就比如说，最近在研究个新的东西，
> 或者方向，然后引导我去生成新的 .md 文件？
> 然后目前也可以引导我去用问答的形式拿到你想要的东西"

**这是非常关键的产品洞察**。让主人坐下来写一份完整的 `quant.md` 是不现实的——会拖。**应该让档案的维护也是"对话驱动"的**，跟收录一样轻松。

→ 这就是 **project-profile skill** 的设计核心。

## project-profile skill 设计

### 数据模型

```sql
CREATE TABLE projects (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT UNIQUE NOT NULL,        -- 短名，如 'quant'
    display_name TEXT,                 -- 显示名，如 '量化投资'
    file_path TEXT NOT NULL,           -- md 文件路径
    status TEXT,                       -- planning / in-progress / paused / done
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL,
    archived INTEGER DEFAULT 0
);

CREATE TABLE item_projects (
    item_id INTEGER NOT NULL,
    project_id INTEGER NOT NULL,
    relevance INTEGER NOT NULL,        -- 0-100
    reason TEXT,
    created_at TEXT NOT NULL,
    PRIMARY KEY (item_id, project_id)
);
```

### CLI 命令

```bash
project list                          # 看所有项目
project show <name>                   # 看某个项目档案（含关联的 item 数）
project new <name>                    # 引导建立新档案（agent 提问 5-7 个问题）
project update <name>                 # 引导更新（聚焦"卡点变化"和"进度变化"）
project ask <name> <question>         # 关于某个项目问 agent
project link <item_id> <project>      # 手动关联
project unlink <item_id> <project>
project relevance <item_id>           # 看一条 item 跟所有项目的关联度
project archive <name>                # 项目完成 / 暂停
```

### 引导问题清单（agent 用）

新建项目时，agent 按这 7 个问题逐条问主人，**一次问一两个，不要列表轰炸**：

1. **项目叫什么**？给个短名（英文小写）+ 一句话描述
2. **目标**：做完后什么样算成功？（产出 / 能力）
3. **现在做到哪步了**：已做完 vs 还在做 vs 还没开始（列表）
4. **目前最大的卡点 / 想搞懂的事**：3 个以内（如果说不出来就跳过）
5. **代码 / 文档位置**：本机或服务器的路径，便于以后对接
6. **相关技能 / 兴趣标签**：用于打通老库存
7. **节奏**：每天 / 周末 / 不定期？

agent 收到答复后，整理成 markdown 档案写入 `/www/knowledge/projects/<name>.md`。

### 触发条件（agent 主动引导）

| 场景 | Agent 行为 |
|------|-----------|
| 主人说"我最近在研究 X" / "我开始做 Y 了" | "听起来是个新方向，要不要建一个项目档案？我问你 5 个问题就行。" |
| 主人说"我项目进度更新了 / 现在卡在 Z" | "我去翻一下你 `quant.md`，把这个卡点加进去，再帮你看看库里有没有相关内容。" |
| 收录新内容时**关联不上任何现有 project**（所有 relevance < 30）| "这条内容好像不在你现有的项目范围里，是新方向吗？要不要建一个 `<推断的名字>.md` 项目档案？" |
| 周报里发现新冒头主题 | "本周你关注了 X、Y，但库里没有对应的项目档案。要不要给 X 起一个？" |
| 主人问"我的 X 项目进度咋样" | 看 `x.md` 的 updated_at，如果 > 7 天没更新，问"距离上次更新过了 X 天了，要不要顺便更新一下卡点和进度？" |
| 主人 archive 一条 item，且这是它唯一关联的项目里的最后一条 | "这个项目最后一条内容也归档了，是不是这个项目结了？要不要把项目状态改成 done？" |

### 改造 Ingest Pipeline

在 Step 3 `classify` 和 Step 4 `essence` 之间，加一个 Step 3.5 `project-link`：

```python
# project-link.py
1. 读 step3.json 拿 content + summary
2. 读所有 projects/*.md
3. 调 LLM：评估这条 item 跟每个 project 的关联度 + 原因
4. 输出 step3.5.json，含字段 project_relevance: [{name, relevance, reason}]
```

然后 Step 5 `save` 多一步：写入 `item_projects` 表。

`summary_for_agent` 飞书消息多一段：

```
🎯 跟你正在做的事：
   ⭐ quant (85) — 命中卡点："训练/回测时间分离"
   💡 llm-agent (40) — 多 Agent 协作思路
```

## 实施计划

| Phase | 工作 | 工时 | 价值 |
|-------|------|------|------|
| Phase 0 | 给 cron "no-due 心跳推送"（不再无声）| 30 分钟 | 立刻有感 |
| Phase 1 | projects 表 + `project` 命令骨架 | 1 小时 | 建立地基 |
| Phase 2 | `project new` 对话引导 + SOUL.md 触发规则 | 1.5 小时 | 主人能轻松建档 |
| Phase 3 | Pipeline 加 `project-link` step | 1 小时 | 入库自动关联 |
| Phase 4 | `project update` 对话引导 + 自动反查老库存 | 1 小时 | 完成第 🅳 层 |
| Phase 5 | `project ask` + `digest impact` 场景化检索 | 2 小时 | 完成第 🅲 层 |
| Phase 6 | （远期）对接代码 | 1 天+ | 完成第 🅴 层 |

**Phase 0-3 合计 4 小时**，做完后体验就完全不一样。
