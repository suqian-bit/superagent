# 查重机制

防止重复收藏同主题内容，浪费时间在低水平重复学习上。在 [[02-Ingest-Pipeline#Step 5 save]] 阶段执行。

**两层防御**：
1. **精确匹配**：fingerprint 完全相同
2. **模糊匹配**：token-set Jaccard 相似度 ≥ 0.8

---

## Fingerprint（主题指纹）

在 [[02-Ingest-Pipeline#Step 3 classify]] 阶段由 DeepSeek 生成。

**格式**：3-6 个英文小写单词，连字符分隔，**抓主题骨干**。

| 标题 | 指纹 |
|------|------|
| 「Hermes 多智能体实战教程」 | `hermes-profiles-multi-instance-tutorial` |
| 「Hermes 记忆详解，四层架构一次讲透」 | `hermes-memory-four-layer-architecture` |
| 「懒人炒股，数据分析交给 AI」 | `lazy-quant-ai-agent-dashboard` |
| 「Karpathy 讲 RAG 入门」 | `karpathy-rag-intro` |

### 设计目的

主题相同的内容（不同人讲、不同语种、不同版本）应该撞到同一个指纹，触发"你已经收过类似主题"提示。

**但 LLM 不稳**：同一篇内容可能生成 `hermes-multi-instance-profiles-tutorial` 或 `hermes-profiles-multi-instance-tutorial`（词序颠倒）。所以光精确匹配不够。

---

## Step 1：精确匹配

```python
existing = conn.execute(
    "SELECT id, title, file_path, created_at FROM items WHERE fingerprint = ?",
    (fp,)
).fetchone()
if existing:
    return duplicate(match_type="exact", existing_id=existing["id"], ...)
```

返回信息：

```
⚠️ 重复（精确）：已收过同指纹内容（id=3, 《Hermes记忆详解》, 2026-05-12）。未重复入库。
```

---

## Step 2：模糊匹配（token-set Jaccard）

如果精确没撞，跑模糊算法：

```python
def fp_tokens(fp: str) -> set[str]:
    STOPWORDS = {"the", "a", "an", "of", "for", "to", "and", "in", "with", "guide"}
    raw = re.split(r"[-_\s]+", fp.lower())
    return {t for t in raw if t and t not in STOPWORDS and len(t) >= 2}

def find_similar_fingerprint(conn, new_fp, threshold=0.8):
    tokens_new = fp_tokens(new_fp)
    rows = conn.execute("SELECT id, fingerprint, ... FROM items WHERE archived=0").fetchall()
    for r in rows:
        tokens_old = fp_tokens(r["fingerprint"])
        inter = tokens_new & tokens_old
        union = tokens_new | tokens_old
        jaccard = len(inter) / len(union)
        if jaccard >= threshold:
            return {**r, "jaccard": jaccard, "matched_tokens": sorted(inter)}
    return None
```

### Jaccard 相似度

```
J(A, B) = |A ∩ B| / |A ∪ B|    ∈ [0, 1]
```

阈值 0.8 实测合理（5 个测试 case 全过，见下）。

### 实测用例

| 新指纹 | 跟 id=3 (`hermes-memory-four-layer-architecture`) 比对 | 期望 | 实际 |
|--------|---------|------|------|
| 完全相同 | jaccard = 1.0 | 撞重 | ✅ |
| `memory-architecture-four-layer-hermes`（词序颠倒）| jaccard = 1.0 | 撞重 | ✅ |
| `hermes-four-layer-memory`（缺 architecture）| jaccard = 4/5 = 0.8 | 撞重（临界）| ✅ |
| `hermes-memory-system-deep-dive`（共享 hermes, memory；新增 system/deep/dive）| jaccard = 2/6 ≈ 0.33 | 不撞 | ✅ |
| `hermes-profile-tutorial`（完全无关）| jaccard = 1/6 ≈ 0.17 | 不撞 | ✅ |

### 撞重时给主人的回复

```
⚠️ 重复（模糊）：库里已有类似主题（id=3, 《Hermes记忆详解...》, 2026-05-12）
相似度 80%, 共同关键词：four, hermes, layer, memory
未重复入库。如果新内容确有补充，可手动 merge 或调整指纹后再存。
```

## 历史 Bug：词序颠倒没拦住

修复前（只有精确匹配）：
```
id=1: hermes-multi-instance-profiles-tutorial   (60 分)
id=2: hermes-profiles-multi-instance-tutorial   (60 分)
```
**同一篇视频，因为 LLM 给的词序不同没撞重，浪费了 2 条记录。**

修复方案：加 token-set 模糊匹配（jaccard ≥ 0.8），词序不影响 set 相等性。

修复后清理：把 id=1/2 删掉，只留 id=3（一条真正不同主题的）。

---

## 不会撞重的情况（设计如此）

| 场景 | 行为 |
|------|------|
| 同主题但 jaccard < 0.8 | 当作新条目 |
| 同一作者不同视频 | 不撞（指纹应该不同）|
| archived=1 的旧条目 | 不参与查重（视为已放弃）|
| 完全相同的 URL | **不查 URL**，只查指纹。如果 LLM 给同指纹会撞；不同就不撞 |

## 调整空间

| 想改 | 改哪 |
|------|------|
| Jaccard 阈值（0.8） | `save.py` 的 `find_similar_fingerprint(conn, fp, threshold=0.8)` |
| 停用词 | `save.py` 的 `STOPWORDS` |
| 指纹规则 | `classify.py` 的 PROMPT_TEMPLATE（让 LLM 怎么造）|
| 加 URL 查重 | `save.py` 增加 `SELECT FROM items WHERE source_url = ?` 一次 |

## 未来增强（TODO）

### 1. URL exact match（兜底）

不同人发同一个链接 → 现在 LLM 可能给不同指纹（因为收录时间不同？）。可以加：

```python
# Step 0 (在 fingerprint 之前)
SELECT id FROM items WHERE source_url = ?
if hit: return duplicate(match_type="same_url")
```

### 2. 语义查重（Embedding 相似度）

当库里有上百条时，Jaccard 可能漏掉真正语义相近但词不同的（如 "Anthropic Claude" vs "Anthropic 大模型"）。可以加 embedding 向量比对，cosine similarity ≥ 0.85 → 撞重。

详见 [[11-已知问题与TODO#RAG]]。

### 3. 合并而非拒绝

现在撞重直接拒绝入库，主人想保留新内容里的"补充"就只能手动。未来可以：
- `digest merge <old_id> <new_step4_file>` —— 把新精华追加到老 item 的精华里，标签合并
