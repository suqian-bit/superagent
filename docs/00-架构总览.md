## 三大流

### ① 收录流（用户主动触发）

```
你在飞书发链接
   ↓
Agent 看到 URL，按 SOUL.md 的"意图分流"判断 → 走 Ingest Pipeline
   ↓
5 步 chain（每步输出 _next_action 强制下一步）：

xhs/video "URL"                       ← Step 1 fetch (抓视频转录 / XHS 笔记)
   ↓ _next_action: score --in step1
score                                 ← Step 2 score (五维评分)
   ↓ _next_action: classify --in step2
classify                              ← Step 3 classify (分类 + 标签 + 指纹)
   ↓ _next_action: essence --in step3
essence                               ← Step 4 essence (tier-aware 精华)
   ↓ _next_action: save --in step4
save                                  ← Step 5 save (落盘 md + SQLite)
   ↓ _next_action: null
Agent 回主人 summary_for_agent
```

详见 [[02-Ingest-Pipeline]]。

---

### ② 推送流（cron 定时触发，不依赖用户）

```
crontab: 0 1,5,13 * * *                ← UTC, 对应北京 9/13/21
   ↓
/usr/local/bin/review-push
   ↓
review_pusher.py
   ↓
   ├─ 查 index.db: WHERE next_review_at <= NOW() AND review_enabled=1
   ├─ 排除 push_history 今天已推过的（按日期）
   ├─ 排序: tier A 优先, 最久没复习优先
   ├─ 挑一条该问的 item
   ├─ 从 questions 表随机选一个问题
   ├─ 按模式（soul/associate/apply/drop）构造文案
   └─ 飞书 OpenAPI 直推：
      POST /open-apis/im/v1/messages?receive_id_type=open_id
   ↓
你飞书收到推送
```

详见 [[06-复习系统]] + [[10-飞书集成]]。

---

### ③ 反馈流（用户回复推送时触发）

```
你回飞书：「4」 / 「记得，是检索+增强+生成」 / 「完全忘了」
   ↓
Hermes Gateway 把消息送给 Agent
   ↓
Agent 看到上下文：上一条 Agent 消息是复习推送
   ↓ 按 SOUL.md HARD RULE 之"复习应答处理"
   ↓
1. digest pending-review              ← 查最近 24h pending 的 item_id
2. 判断 quality 1-5（数字直接用 / 文字按映射表）
3. digest review <item_id> <q>        ← SM-2 更新
   ↓
脚本内：
   ├─ items: review_count++, ease ±, idx ±, mastery ±, next_review_at = +N 天
   └─ push_history: 标记 response_quality + response_at
   ↓
Agent 把脚本返回的 summary_for_agent 回主人
"✅ 已记录：记得很好（4/5），下次推送 3 天后"
```

详见 [[06-复习系统]] + [[07-Hermes-Skill链路]]。

## 双 Profile 隔离

服务器上同时跑两个 Hermes profile，互不干扰：

| Profile | Service | 用途 |
|---------|---------|------|
| `default` | `hermes-gateway.service` | 量化助手（旧的）|
| `knowledge` | `hermes-gateway-knowledge.service` | 知识助手（本项目）|

各自独立：API Key / 配置 / 记忆 / 会话 / 飞书 Bot / 用户 open_id。

详见 [[07-Hermes-Skill链路]] 末节"Profile 隔离"。

## 为什么是这个架构

参见 [[meta/设计权衡|设计权衡]]（如果存在的话）。核心点：

1. **流程编排放在工具输出里**（`_next_action`），不是放在 SOUL.md。因为 SOUL.md 是软约束，Agent 会跳步（之前栽过两次）。
2. **md 文件 + SQLite 双写**。md 是真理来源，SQLite 加速查询。
3. **飞书推送绕开 Hermes**。直接调 OpenAPI 比让 Agent 主动 send 稳得多。
4. **评分用脚本调 LLM，不让 Agent 自评**。否则评分维度漂移。
