# 抖音抓取突破

阻塞了大概一周的问题，今天 30 分钟搞定。记录一下找到方案的过程，避免下次踩坑。

---

## 失败 → 成功的路径

### 一开始踩的坑

| 方案 | 结果 | 原因 |
|------|------|------|
| `yt-dlp` 直接 | ❌ `Fresh cookies needed` | 抖音 2024+ a_bogus 签名 |
| 浏览器导出 cookies → yt-dlp | ❌ 还是 reject | yt-dlp 2026.03 extractor 跟不上 |
| httpx 拿匿名 cookies | ❌ | 不是浏览器指纹，被识别 |
| 直接 fetch `www.douyin.com/video/<id>` HTML | ❌ SPA 空壳 | 数据靠 JS 异步加载 |
| `f2` 库（专门抖音 API）| ❌ | API 端点要 a_bogus 签名 |
| `douyin-tiktok-scraper` pip 包 | ❌ | 12 个月没更新 |

**走了一大圈，结论是"必须破解签名 或 用真浏览器"**——然后栽进死胡同。

### 转折点

继续搜的时候发现 [yzfly/douyin-mcp-server](https://github.com/yzfly/douyin-mcp-server)（已归档但代码还在），它声称 `get_douyin_download_link` 不需要 API。**这就奇怪了——它怎么过签名的？**

去看它源码（[`douyin_downloader.py`](https://github.com/yzfly/douyin-mcp-server/blob/main/douyin-video/scripts/douyin_downloader.py)），发现**根本没破签名，而是绕开了**：

```python
share_url = f"https://www.iesdouyin.com/share/video/{video_id}/"
r = requests.get(share_url, headers={"User-Agent": iPhone_UA})
# 解析 window._ROUTER_DATA
```

---

## 关键发现：iesdouyin.com 是抖音的"老分享接口"

抖音有两套接口：

| URL | 反爬强度 |
|-----|---------|
| `www.douyin.com/video/<id>` | 强（a_bogus + X-Bogus + msToken）|
| **`www.iesdouyin.com/share/video/<id>/`** | **弱**（只要 iPhone UA）|

`iesdouyin.com` 是早年抖音的官方分享域名（"i 爱抖音"的拼音）。微信里点开抖音分享，跳的就是这个。

抖音一直保留这个老接口，可能因为：
- 老分享链接还在流通（要保持兼容性）
- 这个接口只服务"分享给非用户看"，本身就是 public 的
- 反爬策略主要针对 `www.douyin.com` 主站和 API 端点

**老接口返回的 HTML 里有 `window._ROUTER_DATA` 嵌入 JSON**，含完整视频元数据：标题、作者、video_id、play_addr（mp4 直链）、统计数据。

## 完整方案

详见 [[../docs/11-已知问题与TODO#已修复 抖音抓取]]。

精简版：

```python
# 1. 短链 → 长链（拿 video_id）
r = httpx.get(short_url, headers={"User-Agent": iPhone_UA}, follow_redirects=True)
video_id = re.search(r"/video/(\d+)", str(r.url)).group(1)

# 2. iesdouyin 老接口（关键！）
r2 = httpx.get(f"https://www.iesdouyin.com/share/video/{video_id}/",
               headers={"User-Agent": iPhone_UA})

# 3. 抽 JSON
m = re.search(r"window\._ROUTER_DATA\s*=\s*(.*?)</script>", r2.text, re.DOTALL)
data = json.loads(m.group(1))

# 4. 在 loaderData 里找视频信息
for k, v in data["loaderData"].items():
    if "videoInfoRes" in v:
        item = v["videoInfoRes"]["item_list"][0]
        mp4_url = item["video"]["play_addr"]["url_list"][0]
        no_watermark = mp4_url.replace("playwm", "play")  # 神奇的字符串替换
        # ...

# 5. 直接 httpx 下载这个 mp4（不需要 cookies，但要 iPhone UA）
```

**实现**：[`douyin_extractor.py`](../docs/08-命令速查#关键路径表)（服务器：`/root/.hermes/profiles/knowledge/skills/_lib/douyin_extractor.py`）。

## 一些观察

### 1. `playwm` → `play` 这个技巧

mp4 URL 里 `playwm`（"play with watermark"）替换成 `play`，直接拿无水印版。这是抖音 CDN 的一个内部约定，**没有验证**。一行 `str.replace` 解决去水印问题。

### 2. iPhone UA 是必须的

试过用 `User-Agent: python-httpx/0.27` → 老接口直接拒接。试过 PC Chrome UA → 也拒接（重定向到登录页）。**只有 iPhone Safari UA 才放行**。

可能因为老接口主要是给"微信里点开看"的移动端服务的，所以只对移动端 UA 友好。

### 3. 重定向链

```
v.douyin.com/2zAFl8tbI14/                                 (短链)
  ↓ 302
www.iesdouyin.com/share/video/7636.../?from_ssr=1&...     (老分享页 含很多参数)
  ↓ 200 HTML
含 window._ROUTER_DATA JSON
```

注意短链直接重定向到老接口，**不经过新接口**。这本身就是好兆头。

### 4. 转录里的有趣信号

第一次跑通后，看转录文本里 base 模型把 "GitHub" 听成 "GitaB"，把 "Agent" 听成 "AGEMT"，把 "拼多多"听成 "脱维同学"——这都是小模型的局限。

**但下一步 DeepSeek 在做 essence 提炼时纠正了"GitHub"**（自动从上下文推断）。AI pipeline 的一个好处：链路上每一步都有"纠错机会"。

## 教训

1. **不要直接信"最难的方案"**。我前面浪费时间在"破解签名"上，其实只需要"找老接口"。
2. **去找已归档但代码还在的项目**。yzfly 的项目归档了，但代码里藏着金子。
3. **耐心读源码，看别人怎么过反爬**。一行 `share_url = f"https://www.iesdouyin.com/share/video/{video_id}/"` 比所有逆向工程都管用。
4. **小处的 hack 经常是答案**。`replace("playwm", "play")` 这种事，反爬团队从来没补过。
