# 智能分类系统

每条内容挂在**两个独立维度**上：

| | Tags（细标签）| Categories（大类）|
|---|---|---|
| 粒度 | 细 | 粗 |
| 数量级 | 一条挂 3-8 个 | 一条挂 1-3 个 |
| 例子 | `Hermes` / `profile` / `多智能体` / `RAG` | `AI` / `投资` / `美食` / `代码` / `政策` |
| 关联度（affinity）| ❌ 没有 | ✅ 0-100 |
| 何时新增 | 任意 | LLM 觉得现有不合适时新增 |
| 用途 | 标签云 / 全文检索辅助 | 主线归档 / Obsidian MOC / 周报分组 |

## 分类工作流（在 [[02-Ingest-Pipeline#Step 3 classify]] 阶段）

```
读 step2.json (已有 score / title / content)
    ↓
查已有大类: SELECT name FROM categories ORDER BY count DESC LIMIT 50
    ↓
塞进 prompt 喂给 DeepSeek，让它决定:
    1. 选 1-3 个大类（复用已有 / 新增）+ 每个 0-100 关联度
    2. 出 3-8 个细标签
    3. 生成 fingerprint（主题指纹）
    ↓
写 step3.json + _next_action: essence
```

### Prompt 节选

```
对以下内容做：
1) 大类分类（1-3 个，带关联度）
2) 细标签（3-8 个）
3) 主题指纹

已有的大类（如果合适请复用，不合适请新增）：
AI、投资、生产力、教程

规则：
1. 大类是粗粒度，少而稳定
   - 一条最多 3 个大类
   - 主大类 affinity >= 80，次大类 30-60
   - 实在不贴边就别硬挂
2. 细标签灵活，优先复用作者已经打的话题（tags_seed）
3. 指纹：3-6 个英文小写单词连字符
   - 例：hermes-profiles-multi-instance-tutorial
```

完整 prompt 在 `classify.py` 的 `PROMPT_TEMPLATE`。

## 关联度（Affinity）— Category 独有

一条内容跟某个大类有多贴边：

| affinity | 含义 |
|----------|------|
| 90-100 | 这条就是这个大类的典型内容 |
| 60-89 | 主要属于这个大类 |
| 30-59 | 沾边，副线分类 |
| < 30 | 不该挂（脚本里建议直接 drop）|

### 实例

```sql
-- id=3 (Hermes 记忆四层架构)
SELECT c.name, ic.affinity
FROM item_categories ic JOIN categories c ON ic.category_id=c.id
WHERE ic.item_id = 3;
-- AI         | 95   ← 主线
-- 生产力     | 50   ← 副线（提到效率）
```

## 动态新增大类

LLM 在 prompt 里看到已有 categories 列表，决定：
- 内容明显能塞进现有 → 复用
- 内容代表新方向 → 自己起名，写到 `categories: [{name: "新名字", ...}]`

`save.py` 写入时：
```python
row = conn.execute("SELECT id FROM categories WHERE name=?", (name,)).fetchone()
if row:
    cat_id = row["id"]
    conn.execute("UPDATE categories SET count=count+1 WHERE id=?", (cat_id,))
else:
    cur = conn.execute(
        "INSERT INTO categories (name, description, count, created_at) VALUES (?, ?, 1, ?)",
        (name, cat.get("reason", ""), now),
    )
```

**第一次创建时把 LLM 给的 reason 存进 description 字段**，可以后续看每个分类是怎么被命名的。

## 标签（Tags）— 复用作者已有

`tags_seed` 来自原始平台数据：
- 小红书：作者打的 `#话题`
- B站：UP 主在描述里写的

LLM 优先复用这些（避免乱造），合理再补充：

```
tags_seed: ["HermesAgent", "AI工具", "多实例", "效率工具", "AI助手", "profiles", "本地AI"]
        ↓ LLM 整理
tags:      ["HermesAgent", "AI记忆机制", "AI工具", "Agent教程", "Hermes教程", "AI效率工具"]
```

## 查询能力

### 看库里有哪些分类

```bash
digest stats
# {"categories": [{"name": "AI", "count": 12}, {"name": "投资", "count": 5}, ...]}
```

### 按分类查 item

```bash
digest by-cat AI --min-affinity 80
# 列出所有 AI 关联度 >= 80 的 item
```

### 按标签查 item

```bash
digest by-tag Hermes
# 列出所有打了 #Hermes 的 item
```

详见 [[08-命令速查]]。

## 周报应用（TODO）

未来周报 cron 会按 category 分组：

```sql
SELECT c.name, COUNT(*), AVG(i.score_total)
FROM item_categories ic
JOIN categories c ON ic.category_id=c.id
JOIN items i ON ic.item_id=i.id
WHERE i.created_at >= DATE('now', '-7 days')
  AND ic.affinity >= 70
GROUP BY c.name
ORDER BY COUNT(*) DESC;
```

每个 category 挑 weight Top 3 → LLM 写一段总结 → 飞书推送。
