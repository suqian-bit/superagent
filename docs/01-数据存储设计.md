# 数据存储设计

**设计原则**：md 文件 = 真理来源，SQLite = 查询加速。两份冗余，丢一份能从另一份重建。

---

## 顶层目录布局

```
/www/knowledge/                           ← 知识库根
├── items/                                ← 每条收录内容一个 md 文件
│   └── YYYY-MM-DD/
│       └── 0001_<指纹>.md
├── index.db                              ← SQLite 索引
├── essence/                              ← 预留：精华独立目录（当前没用）
├── categories/                           ← 预留：分类 MOC（当前没用）
└── attachments/                          ← 预留：视频/图片附件
```

### 路径规则

- **目录按天分**：避免单目录上千文件。日期取**北京时间**（[[09-时区与时间约定]]）。
- **文件名 `<id4>_<指纹-slug>.md`**：id 是 SQLite 自增，4 位补零；指纹是 LLM 生成的英文小写连字符（见 [[05-查重机制]]）。

### 临时工作目录

```
/tmp/ingest/                              ← Pipeline 步骤文件，运行时使用
└── <run_id>_step{1,2,3,4}.json
```

每条 ingest 链路一个 run_id，4 个 step file 在链路过程中累积。失败可以从任一 step 重启。完成后保留供调试，可定期清理。

## md 文件结构

每条 item 一个 `.md`，由 [[02-Ingest-Pipeline#Step 5 save]] 的 `save.py` 生成。

```markdown
---
id: 3
fingerprint: hermes-memory-four-layer-architecture
title: "Hermes记忆详解，四层架构一次讲透"
platform: xiaohongshu
uploader: "麦冬AI实验室"
source_url: http://xhslink.com/o/7L7T4FdGYDm
created_at: 2026-05-12T14:07:52+08:00
tier: A
weight: 95
scores:
  density: 20
  actionable: 22
  uniqueness: 18
  reliability: 15
  reusability: 20
  total: 95
tags: ["HermesAgent", "AI记忆机制", "AI工具", ...]
categories:
  AI: 95
  生产力: 50
review:
  enabled: true
  next: 2026-05-13T14:07:52+08:00
  count: 0
  mastery: 0
---

## 一句话核心
（30 字以内）

## 评分要点
- ✅ 亮点：（一句）
- ⚠️ 弱点：（一句）

## 精华
（tier A: 约 400 字, B: 约 200 字, C: 约 100 字。markdown 结构化）

## 反思问题
1. ...
2. ...
3. ...

## 完整原文
（视频转录 / 网页正文，**完整保留，未做删减**）
```

### Frontmatter 字段说明

| 字段 | 类型 | 含义 |
|------|------|------|
| `id` | int | SQLite 自增 ID，跟文件名前缀对齐 |
| `fingerprint` | str | 主题指纹（3-6 词连字符），查重 key |
| `tier` | str | `A` / `B` / `C`，对应 score_total ≥90 / 80-89 / <80 |
| `weight` | int | 0-100，初始 = score_total，未来动态调整（被引用、被复习等）|
| `scores.*` | int×5 | 五维评分，每维 0-25 |
| `tags` | str[] | 细标签，3-8 个 |
| `categories.<name>` | int | 大类 + 关联度（affinity 0-100）|
| `review.enabled` | bool | 是否启动间隔复习。tier A 自动启用 |
| `review.next` | iso8601 | 下次推送时间（北京时间）|
| `review.count` | int | 累计被推送 + 用户答过几次 |
| `review.mastery` | int | 0-100 掌握度，答对 +15, 答错 -10 |

## SQLite Schema (`/www/knowledge/index.db`)

由 `save.py` 在第一次运行时通过 `init_db()` 创建。

### items —— 主表

```sql
CREATE TABLE items (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    fingerprint TEXT UNIQUE NOT NULL,         -- 主题指纹（查重 key）
    platform TEXT,                            -- xiaohongshu / bilibili / ...
    title TEXT,
    uploader TEXT,
    source_url TEXT,
    file_path TEXT NOT NULL,                  -- 指向 md 文件绝对路径
    tier TEXT,                                -- A / B / C
    weight INTEGER,                           -- 0-100
    -- 五维评分
    score_total INTEGER,
    score_density INTEGER,
    score_actionable INTEGER,
    score_uniqueness INTEGER,
    score_reliability INTEGER,
    score_reusability INTEGER,
    summary_one_line TEXT,
    created_at TEXT NOT NULL,                 -- 北京时间 ISO
    -- 复习相关（[[06-复习系统]]）
    review_enabled INTEGER DEFAULT 0,
    review_idx INTEGER DEFAULT 0,             -- 当前在 REVIEW_INTERVALS 的第几位
    ease REAL DEFAULT 2.5,                    -- SM-2 ease factor
    review_count INTEGER DEFAULT 0,
    last_reviewed_at TEXT,
    next_review_at TEXT,
    mastery INTEGER DEFAULT 0,                -- 0-100
    archived INTEGER DEFAULT 0                -- 1 = 主人选择放弃
);

CREATE INDEX idx_fingerprint ON items(fingerprint);
CREATE INDEX idx_next_review ON items(next_review_at)
    WHERE review_enabled=1 AND archived=0;
CREATE INDEX idx_created ON items(created_at DESC);
```

### tags / item_tags —— 细标签（多对多）

```sql
CREATE TABLE tags (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT UNIQUE NOT NULL,
    count INTEGER DEFAULT 0,                  -- 该标签出现过的 item 数
    created_at TEXT NOT NULL
);

CREATE TABLE item_tags (
    item_id INTEGER NOT NULL,
    tag_id INTEGER NOT NULL,
    PRIMARY KEY (item_id, tag_id)
);
```

### categories / item_categories —— 大类（多对多 + 关联度）

```sql
CREATE TABLE categories (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT UNIQUE NOT NULL,                -- AI / 投资 / 美食 / 代码 ...
    description TEXT,                         -- LLM 第一次创建时的解释
    count INTEGER DEFAULT 0,
    created_at TEXT NOT NULL
);

CREATE TABLE item_categories (
    item_id INTEGER NOT NULL,
    category_id INTEGER NOT NULL,
    affinity INTEGER DEFAULT 0,               -- 关联度 0-100
    PRIMARY KEY (item_id, category_id)
);
```

详见 [[04-智能分类系统]]。

### questions —— 反思问题

```sql
CREATE TABLE questions (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    item_id INTEGER NOT NULL,
    question TEXT NOT NULL
);
```

每条 item 在 essence 阶段生成 2-3 条反思问题，复习推送时随机选一条问。

### push_history —— 推送历史（[[06-复习系统]] 用）

```sql
CREATE TABLE push_history (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    item_id INTEGER NOT NULL,
    question TEXT NOT NULL,                   -- 本次推送的问题
    mode TEXT NOT NULL,                       -- soul / associate / apply / drop
    pushed_at TEXT NOT NULL,
    response_at TEXT,                         -- 用户回复时间（NULL = 还没答）
    response_quality INTEGER                  -- 用户回的 1-5 分（NULL = 没答）
);

CREATE INDEX idx_push_item ON push_history(item_id, pushed_at);
```

每次 review-push 推送一条就 insert 一行。`response_quality IS NULL` 的就是 pending。

## 双写策略

入库时（[[02-Ingest-Pipeline#Step 5 save]]）：

```
data (step4.json)
  │
  ├─→ INSERT items (拿到 id)
  │
  ├─→ 写 md 文件到 /www/knowledge/items/<date>/<id>_<fp>.md
  │     ├─ frontmatter（来自 SQLite 字段 + categories/tags）
  │     ├─ 一句话核心 / 评分要点 / 精华 / 反思 / 完整原文
  │
  ├─→ UPDATE items SET file_path=<md 路径> WHERE id=<id>
  │
  ├─→ INSERT INTO questions × N
  │
  ├─→ UPSERT tags + INSERT item_tags
  │
  └─→ UPSERT categories + INSERT item_categories
```

|------|------|

## 占用空间估算（每条平均）

| 项 | 大小 |
|------|------|
| md 文件 | 5-15 KB（含转录原文）|
| SQLite 行 | < 1 KB |
| 下载的 mp3 | 2-5 MB（可清，已转录的不需要保留）|
| 下载的 mp4 | 8-20 MB（可清）|
| Whisper 模型（base 一次性）| ~150 MB |

**结论**：1000 条只占用约 10-15 MB（不含原始 mp3/mp4，那些可定期清理）。
