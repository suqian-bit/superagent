# 项目档案与关联

> **核心目标**：让助理**知道主人在做什么**，从"被动仓库"进化成"主动连接"。
> 主人正在做事时，库存能主动跳出来说"这条对你有用"，而不是等主人想起来。
>
> 详细产品思考见 [[../meta/2026-05-14-从仓库到助理]]。

---

## 概念模型

```
项目档案（projects/<name>.md + projects 表）
       │
       │ 关联（item_projects 表，含 relevance 0-100）
       │
       ▼
 已收录内容（items 表）
```

每条收录的内容（item）可以跟 0-N 个项目（project）关联，每条关联带：
- `relevance`（0-100）：关联度
- `reason`：一句话说明为啥相关

---

## 数据结构

### `projects` 表

```sql
CREATE TABLE projects (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT UNIQUE NOT NULL,        -- 短名，如 'quant' / 'llm-agent'
    display_name TEXT,                 -- 显示名，如 '量化投资'
    file_path TEXT NOT NULL,           -- 对应的 md 档案位置
    status TEXT DEFAULT 'in-progress', -- planning / in-progress / paused / done
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL,
    archived INTEGER DEFAULT 0
);
```

### `item_projects` 关联表

```sql
CREATE TABLE item_projects (
    item_id INTEGER NOT NULL,
    project_id INTEGER NOT NULL,
    relevance INTEGER NOT NULL,        -- 0-100
    reason TEXT,
    created_at TEXT NOT NULL,
    PRIMARY KEY (item_id, project_id),
    FOREIGN KEY (item_id) REFERENCES items(id),
    FOREIGN KEY (project_id) REFERENCES projects(id)
);
```

### 项目档案 md 文件

`/www/knowledge/projects/<name>.md`，每个项目一个文件。

```markdown
---

created: 2026-05-13
updated: 2026-05-14
```

## 命令：`project`

```bash
project questions                       # 拿引导问题清单（agent 用）
project list [--all]                    # 看所有项目
project show <name>                     # 看某个项目档案 + 关联 items
project new <name> '<json>'             # 建新档案（自动反扫老库存）
project new <name> - < answers.json     # 从 stdin 读
project update <name> --section <sec> --text "..." --mode append/replace
project link <item_id> <name> <relevance> [--reason "..."]
project unlink <item_id> <name>
project relevance <item_id>             # 看一条 item 跟所有 project 的关联
project archive <name> [--status done/paused]
```

### `--section` 可选值

| section | 对应 md 段落 |
|---------|------------|
| `goal` | 🎯 目标 |
| `progress` | 📊 当前进度 |
| `pain_points` | ⚠️ 当前卡点 |
| `code_location` | 📂 代码 / 文档位置 |
| `tags` | 🏷 相关技能 / 兴趣 |
| `cadence` | 🕒 推进节奏 |
| `notes` | 📌 备注 |

## 引导问答（agent 主动建档案的核心机制）

让主人不用坐下来写 md，而是被 agent 引导着说出来。

### 7 个问题（`project questions` 返回）

```python
QUESTIONS = [
    {"key": "name_and_pitch", "ask": "这个项目叫什么？给个英文短名 + 一句话描述", ...},
    {"key": "goal",          "ask": "目标是什么？做完后什么算成功？", ...},
    {"key": "progress",      "ask": "现在做到哪步了？分 ✅/🚧/⏳ 三段", ...},
    {"key": "pain_points",   "ask": "目前最大的卡点 / 想搞懂的？最多 3 个", ...},
    {"key": "code_location", "ask": "项目代码 / 文档在哪？", ...},
    {"key": "tags",          "ask": "相关技能 / 兴趣标签？", ...},
    {"key": "cadence",       "ask": "打算用什么节奏推进？", ...},
]
```

### Agent 收集节奏（SOUL.md 强约束）

```
1. 先问 name_and_pitch（确认短名）
2. 一次问 goal + progress
3. 单独问 pain_points（最重要的字段）
4. 一次问 code_location + tags + cadence
```

中途主人不耐烦 / 说"先这样吧" → 用空字符串占位剩余字段，**先建出来**，以后 `project update` 补全。

### 6 个触发场景（SOUL.md HARD RULE）

| 主人说的话 | Agent 应该做 |
|----------|------------|
| "我最近在研究 X" / "我开始做 Y 了" | `project list` 检查 → 没有就 `project questions` → 引导对话 |
| "我项目进度更新了" / "现在卡在 W 上" | `project update <name> --section pain_points --text "..." --mode append` |
| "X 项目咋样了？" | `project show X` 然后用 markdown 内容跟主人聊 |
| "把 id=5 关联到 quant" | `project link 5 quant 90 --reason "..."` |
| "这个项目不做了" / "归档 X" | `project archive X --status paused` 或 `done` |
| 收录新内容时**关联不上任何现有项目** | "这是新方向吗？要不要建项目档案？" |

## 自动关联机制（**Phase 3：入库即评估**）

### Pipeline 集成

Step 3 `classify` 跑完分类+打标签+指纹后，**额外调一次 DeepSeek 评估这条内容跟所有现有项目的关联度**。

```python
# classify.py 末尾
out["project_relevance"] = evaluate_project_relevance(out)
```

### 评分规则（prompt 固化）

```
| 关联度 | 含义 |
|-------|------|
| 90-100 | 直接命中项目卡点 / 提供具体可用方法 |
| 70-89  | 主题强相关，能补充思路 |
| 40-69  | 部分相关，间接有启发 |
| < 40   | 基本不相关，不入库

只保留 relevance >= 40 的写入 project_relevance 字段。
```

### Step 5 save 写入 `item_projects`

```python
# save.py
for rel in data["project_relevance"]:
    project_id = lookup_by_name(rel["project"])
    INSERT INTO item_projects (item_id, project_id, relevance, reason, created_at)
    UPDATE projects SET updated_at = NOW() WHERE id = project_id  # 项目更新时间也刷新
```

### summary_for_agent 多一段

```
📌 一句话核心
🏷 #tag1 #tag2
📂 AI(95) / 投资(85)

🎯 跟你正在做的项目
  ⭐ quant (95) — 命中卡点：训练/回测时间分离
  💡 llm-agent (60) — 多 Agent 协作思路

━━━━━━━━━━━━━━━━━━
💎 精华...
```

主人在飞书**入库当下就能看到"这条值不值得立刻用"**。

## 反扫老库存（**Phase 4：建项目时自动找老内容**）

每次 `project new <name>` 之后，自动跑一次：

```python
# project.py 的 backscan_old_items()
1. 拿当前所有 archived=0 的 items（最多 50 条，按 weight 排）
2. 调 DeepSeek 批量评估每条 vs 新项目的关联度
3. relevance >= 60 的自动 INSERT 进 item_projects
4. 给主人返回 "找到 N 条相关老内容，建议先看 id=X、id=Y"
```

### 实测

建 `ai-coding` 项目（关注 AI 辅助编程 / OpenSpec / 多 Agent）：

```
🔁 反扫老库存：在 5 条已收录里发现 2 条跟 `ai-coding` 相关：
  [95] id=6 精讲OpenSpec，从操作到原理 Vibe Coding 总是做偏？
  [70] id=3 Hermes记忆详解，四层架构一次讲透
```

跳过反扫：`project new <name> '<json>' --no-backscan`。

## 场景化检索（**Phase 5：主人卡住了就翻库**）

```bash
digest impact "<场景的自然语言描述>"
```

### 触发场景

| 主人说 | Agent 应该调 |
|-------|------------|
| "我现在要做 X / 改 Y / 写 Z" | `digest impact "<原话>"` |
| "我卡在 W 上 / 怎么搞 W" | `digest impact "<原话>"` |
| "有没有 X 相关的" | `digest impact` 或 `digest by-tag X` |

### 实现

```python
def cmd_impact(scenario):
    1. 调 LLM 把场景拆成：
       - matched_project（最可能跟哪个项目相关）
       - keywords（3-5 个检索关键词）
    2. 多渠道检索：
       a. 如果有 matched_project → 拿该项目下 relevance >= 60 的 items（权重 ×1.5）
       b. 用 keywords 在 items 表的 title / summary / tags 里 LIKE 搜
    3. 按 score 排序，取 Top 8
    4. 拼 summary_for_agent
```

### 实测

```bash
digest impact "我现在要给 momentum 策略加多时间周期"
```

```
🔍 跟「我现在要给 momentum 策略加多时间周期」相关的库存：
   （识别到项目：quant）

1. [A·95] id=5 AI干货分享-AI炒股
   分享使用AI进行股票交易的策略和心得
   ↳ 项目 quant 关联 95 / 关键词命中 `回测`

💡 想看哪条详细内容？回我「看 id=X」
```

### 找不到的兜底

如果 `results: []`，agent 应该回："库里没找到相关的。这是新方向吗？要不要建项目档案？" → 走 [[#引导问答]]。

## 完整使用流程

```
你飞书说"我最近在研究 K8s 运维"
   ↓
agent → project list（看是否已有）
   ↓ 没有
agent → project questions（拿引导清单）
   ↓
agent 按节奏问主人 1-2 个问题
   ↓ 主人答完 7 个
agent → echo '<answers json>' | project new k8s-ops -
   ↓ 自动触发：
   ① 写 /www/knowledge/projects/k8s-ops.md
   ② 反扫老库存：评估 50 条 items vs 新项目，relevance >= 60 自动 link
   ↓
agent 回复："✅ 建好了，找到 N 条相关老内容..."

—————————————————

你之后再发链接 → ingest pipeline 跑 5 步
   ↓ Step 3 classify
   ↓ 多调一次 LLM 评估 vs 所有 projects
   ↓ Step 5 save
   ↓ 写 item_projects + summary 多一段 🎯 跟项目
   ↓
飞书消息里直接看到："⭐ k8s-ops (85) — 命中卡点：xx"

—————————————————

你工作时说"我卡在 K8s ingress 配置上"
   ↓
agent → digest impact "我卡在 K8s ingress 配置上"
   ↓ 识别 matched_project=k8s-ops
   ↓ 关键词命中 + 项目关联综合排序
   ↓
返回 Top 5 相关 items：库里有几条历史收藏直接能用
```
